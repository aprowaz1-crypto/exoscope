# Алгоритми ExoScope

Документ описує науковий конвеєр застосунку, припущення та обмеження. Усі обчислення виконуються локально у браузері на TypeScript.

---

## 1. Читання FITS

Парсер підтримує:

- `BITPIX`: 8, 16, 32, −32, −64;
- `BSCALE` / `BZERO`;
- `GCOUNT` / `PCOUNT`;
- `NAXIS=2` (зображення) і `NAXIS=3` (куб; кожна площина — окремий кадр);
- бінінг великих кадрів до 1536 px за найбільшою стороною (усереднення блоків).

Значення зберігаються у `Float32Array`. Фізичне калібрування (dark/flat/bias) не виконується: очікуються вже відкалібровані кадри.

Часові заголовки читаються у такому порядку: `BJD_TDB`, `BJD`, `HJD`, `JD`, `MJD-OBS`, `MJD`, `DATE-OBS`. `MJD` переводиться у JD додаванням 2 400 000.5. Для `DATE-OBS` додається половина `EXPTIME`, щоб отримати середину експозиції. Якщо жодного часу немає, використовується заданий початковий JD і постійний крок.

---

## 2. Виявлення зірок

1. Кадр ділиться на тайли (до 32×32). Для кожного тайла рахуються медіана та MAD.
2. Локальні оцінки фону й шуму білінійно інтерполюються на кожен піксель.
3. Поріг: `background + thresholdSigma × noise`.
4. Пікселі вище порогу групуються у 8-звʼязні компоненти.
5. Для кожного компонента:
   - зважений центроїд за потоком над фоном;
   - сумарний потік і пік;
   - FWHM за другим центральним моментом;
   - елонгація як відношення осей;
   - SNR за сумарним потоком і шумом;
   - прапорець насичення, якщо пік близький до `SATURATE` з заголовка.

Повертається список зірок, відсортований за потоком.

---

## 3. Вирівнювання кадрів

Оцінюється подібнісне перетворення:

```
x' = a·x − b·y + tx
y' = b·x + a·y + ty
```

де `a = s·cos θ`, `b = s·sin θ`.

Алгоритм:

1. Зорі референсного та поточного кадрів нормалізуються за середнім потоком.
2. Гістограма попарних зсувів (з урахуванням різниці положень) дає початкове наближення `(tx, ty)`.
3. Ітеративне зіставлення за найближчим сусідом у межах допуску.
4. Зважений МНК за зіставленими парами дає `a, b, tx, ty`.
5. Обчислюється RMS залишків і кількість зіставлених зірок; ненадійні трансформації позначаються.

Для фотометрії положення зорі в кожному кадрі зсувається за трансформацією; субпіксельне значення потоку береться з інтерполяцією.

---

## 4. Апертурна фотометрія

Для кожної зорі та кожного кадру:

1. Апертура радіуса `r_ap = apertureFactor × FWHM`.
2. Кільце неба: внутрішній радіус `r_ap + annulusGap`, зовнішній `r_ap + annulusGap + annulusWidth`.
3. Медіана та MAD у кільці дають локальний фон і шум.
4. Потік: сума `(pixel − sky)` в апертурі з субпіксельною вагою.
5. Дисперсія:

```
σ² = (F / gain) + A·(sky / gain) + A·(readNoise / gain)² + (A·σ_sky)²
```

де `A` — площа апертури, `F` — потік у електронах, `sky` — фон на піксель.

Якщо `GAIN` або `READNOISE` відсутні, використовуються значення з налаштувань; це впливає на абсолютну шкалу похибок, але не на диференціальну криву.

---

## 5. Диференціальна крива світла

1. Для кожної зорі обчислюється середній потік у часовому ряду.
2. Кандидати у зорі порівняння відсіваються за аномальним RMS (`variableClip` × медіанний RMS).
3. Кожна зоря порівняння нормується на свій середній потік.
4. Ансамбль зважується оберненою дисперсією; отримується референсна крива.
5. Цільова зоря ділиться на ансамбль: `flux = target / ensemble`.
6. Сигма-кліпінг за `clipSigma` виключає викиди.
7. За потреби застосовується бінінг за часом із зваженим середнім.

Детрендинг — зважена лінійна або квадратична регресія за часом і, опційно, за FWHM, фоном, airmass і зсувом центроїда. Коефіцієнти оцінюються разом із вільним членом; тренд ділиться на модель.

---

## 6. BLS-пошук періоду

Box-Least-Squares (BLS) сканує:

- логарифмічну сітку періодів між `minPeriod` і `maxPeriod`;
- сім тривалостей від `minDurationHours` до `maxDurationHours`;
- усі фази для кожного періоду з кроком `1/nBins`.

Для кожного періоду обчислюється покращення χ² відносно постійної моделі при заміні інтервалу тривалістю `T` на глибину `d`. Обирається найкраща комбінація `(period, duration, phase)`.

Після грубого пошуку виконується локальне уточнення періоду та фази. Спектр зберігається для графіка. SDE (signal detection efficiency) обчислюється як:

```
SDE = (score_max − mean(score)) / std(score)
```

SDE залежить від ширини та кореляції піків; це не p-value і не ймовірність відкриття. Сильні транзити можуть давати SDE ≈ 5–8 через розширення спектра.

BLS виконується у Web Worker. Якщо Worker недоступний (наприклад, `file://`), використовується синхронна реалізація.

---

## 7. Трапецієподібна модель транзиту

Модель описується параметрами:

- `P` — період;
- `T₀` — центральна епоха;
- `d` — глибина (частка потоку);
- `T₁₄` — повна тривалість;
- `T₁₂` — тривалість ingress/egress (плоске дно відсутнє, якщо `T₁₂ ≈ T₁₄`).

Профіль:

- поза транзитом: `1`;
- під час ingress/egress: лінійний перехід між `1` і `1 − d`;
- на дні: `1 − d`.

Фіт виконується Нелдером–Мідом у перетворених координатах (`log P`, `log d`, `log T₁₄`, `log T₁₂`) з обмеженнями. Початкове наближення береться з BLS-піку. Похибки параметрів оцінюються з чисельного гессіана в точці мінімуму:

```
Cov ≈ 2·H⁻¹·χ²_red
```

де `H` — гессіан χ². Якщо гессіан погано обумовлений, похибка позначається як недоступна.

Додатково рахуються:

- `SNRt` — глибина / медіанна похибка точок у транзиті;
- `χ²/dof`;
- RMS залишків;
- глибина кожного транзитного Events (odd/even);
- прапорець періоду на межі діапазону.

---

## 8. Веттинг транзитного кандидата

Перевірки:

| Перевірка | Що робить |
|---|---|
| Odd–even | Порівнює глибини парних і непарних транзитів; велика різниця → затменна подвійна. |
| Вторинний мінімум | Шукає затемнення на фазі 0.5; глибокий вторинний мінімум → подвійна зоря. |
| Зсув центроїда | Перевіряє, чи змінюється положення центроїда під час транзиту (блендинг). |
| Red noise | Порівнює RMS бінованих залишків із фотонним шумом. |
| Форма | Перевіряє `T₁₂/T₁₄`; занадто V-подібний профіль підозрілий. |
| Насичення | Позначає насичені зорі. |
| Блендинг | Шукає близьких сусідів у межах кількох FWHM. |

Вердикт (`strong`, `candidate`, `weak`, `false-positive`, `insufficient`) — евристична оцінка, не статистичний тест.

## 9. Пряме зображення: ADI/RDI

### 9.1 Центр і вирівнювання

Найяскравіша зоря знаходиться box-фільтром (інтегральне зображення) та зваженим центроїдом. Кожен кадр зсувається білінійно так, щоб центр зорі збігався з референсним.

### 9.2 PSF-референс

Медіанний стек вирівняних кадрів дає референсну PSF `R(x, y)`. Для кожного кадру:

```
residual_i = frame_i − R
```

Це RDI-крок. У режимі ADI залишок обертається на кут поля `θ_i` навколо центра:

```
residual_i^rot(x, y) = residual_i(x·cos θ_i + y·sin θ_i, −x·sin θ_i + y·cos θ_i)
```

Потім залишки усереднюються:

```
combined(x, y) = mean_i residual_i^rot(x, y)
```

Планета, яка обертається разом із полем, додається когерентно; статичні спекли послаблюються.

Кути: `PARANG` із заголовків, ручний початковий кут + крок, або режим без обертання (RDI).

### 9.3 Шум і карта SNR

Комбіноване зображення ділиться на радіальні кільця шириною 2 px. У кожному кільці рахуються медіана та MAD. Для пікселя на радіусі `r` шум `σ(r)` інтерполюється між сусідніми кільцями.

```
SNR(x, y) = combined(x, y) / σ(r)
```

Кандидати — локальні максимуми `SNR ≥ threshold` у кільці між `minSeparation` і `maxSeparation`. Після відбору центроїд уточнюється у вікні 5×5 px.

### 9.4 Контрастність

Для кожного радіального біна:

```
contrast_1σ(r) = σ(r) / peak_star
contrast_5σ(r) = 5·σ(r) / peak_star
Δmag(r) = −2.5·log₁₀(contrast_5σ)
```

Крива показує граничний контраст на даній відстані. Вона не враховує систематику PSF, помилки кутів і кореляцію шуму між кадрами.

---

## 10. Обмеження та продуктивність

- Браузерна памʼять обмежує набір ~60 млн пікселів; великі кадри бінінгуються.
- Фотометрія обробляє кадри частинами, щоб інтерфейс залишався живим.
- BLS у Worker не блокує вкладку, але на повільних пристроях може тривати десятки секунд.
- ADI обробляє задану кількість рівномірно вибраних кадрів.
- Немає калібрування dark/flat/bias, деблендингу, PSF-фітингу та MCMC; результати слід інтерпретувати як попередній аналіз.

## English overview

The same pipeline is implemented in TypeScript and runs entirely in the browser:

1. **FITS ingestion** — integer/float BITPIX, BSCALE/BZERO, data cubes, binning.
2. **Star detection** — tiled background/MAD maps, adaptive threshold, connected components, subpixel centroids, FWHM/elongation.
3. **Alignment** — similarity transform via shift histogram, nearest-neighbour matching and weighted least squares.
4. **Aperture photometry** — subpixel apertures, sky annulus, photon/read/sky noise budget.
5. **Differential light curve** — inverse-variance ensemble, variable-star rejection, sigma clipping, detrending and binning.
6. **BLS** — log period grid, multiple durations, all phases, local refinement; runs in a Web Worker.
7. **Trapezoid transit fit** — Nelder–Mead in transformed coordinates, numerical-Hessian uncertainties, SNRt, χ², per-event depths.
8. **Vetting** — odd–even, secondary minimum, centroid shift, red noise, shape, saturation, blending.
9. **ADI/RDI** — brightest-star centring, subpixel alignment, median PSF reference, residual rotation and mean combination.
10. **Detection limits** — radial MAD noise, SNR map, candidate peaks and 1σ/5σ contrast curves.

All results are candidates requiring independent follow-up. The tool is intended for research and education, not as a certified discovery pipeline.
